# simple-cms: agent guidance

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind v4 + MongoDB + NextAuth v5 beta. A marketing site with an authenticated admin area. It runs on the platform at `https://<cf>/simple-cms/`. Platform-wide rules are in the root [`AGENTS.md`](../../AGENTS.md).

## Commands (run in `apps/simple-cms`)

```bash
npm install
npm run dev              # http://localhost:3000/simple-cms, admin at /simple-cms/admin/login
npm run build            # output: "standalone" (used by the Dockerfile)
npm run lint
npx tsc --noEmit --incremental false
npm run mongo:memory     # in-memory MongoDB when Docker isn't available
npm run seed             # WIPES and reseeds all collections, incl. admin user
```

There is no test suite. Before finishing a change, run `npm run lint` and `npx tsc --noEmit --incremental false`; CI runs both.

Env: copy `.env.local` from the template literally named `.env example`. It sets `MONGODB_URI`, `AUTH_SECRET`, `AUTH_URL` (origin only, no path), `ADMIN_EMAIL` and `ADMIN_PASSWORD`.

## Base path

`next.config.ts` sets `basePath: "/simple-cms"` and inlines `NEXT_PUBLIC_BASE_PATH`. Next adds the prefix to `<Link>`, `redirect()`, `router.push()` and `_next` assets. Wrap these with `withBasePath()` from `lib/base-path.ts`:

- raw `fetch("/api/...")` calls
- string `<Image src>` values
- CSS `url()`
- next-auth client callback URLs

Image paths in Mongo are stored unprefixed.

If the base path changes, `terraform/apps/simple-cms/main.tf` (`path`, `health_path`) and `.github/workflows/app-simple-cms.yml` (`health_path`) must change with it.

## Auth

- `lib/auth.config.ts` is provider-less. `middleware.ts` uses it to guard `/admin/:path*` (except `/admin/login`). The middleware doesn't cover `/api`.
- `lib/auth.ts` adds the Credentials provider (bcrypt against `users`).
- Server-side, Auth.js keeps its default basePath `/api/auth`, because Next strips `/simple-cms` before route handlers. Setting `/simple-cms/api/auth` server-side breaks with `UnknownAction`.
- The client `SessionProvider` (`components/admin/Providers.tsx`) uses `/simple-cms/api/auth`.
- Cookies are named `simple-cms.*` with `Path=/simple-cms`, and get `Secure` when `AUTH_URL` is https.
- API routes enforce auth with `requireAdmin()` in `lib/api-auth.ts`.

## Data

- `lib/mongodb.ts` caches one `MongoClient` on `global`. The DB name comes from the URI path.
- Server components use the read helpers in `lib/data.ts` directly.
- Public `(site)` and admin list pages are `force-dynamic`.
- Collections: `products`, `categories`, `mediaItems`, `storySections`, `events`, `pageContent`, `registrations`, `users`.

## Generic CRUD API

- Most `app/api/<resource>/route.ts` and `[id]/route.ts` files are one-liners over `makeCrudHandlers` / `makeCrudIdHandlers` (`lib/crud.ts`), with a Zod schema from `lib/schemas.ts`.
- These require an admin session for every method, GET included.
- Adding a resource = schema + type in `models/types.ts` + two route files + admin pages/form.

Exceptions:

- `api/registrations` POST is public.
- `api/health` is unauthenticated. It must stay free of DB and secret access, because the CI smoke test runs the container bare.
- `api/seed` (admin POST) imports `scripts/seed.ts`. That script is therefore bundled into the app as well as run via `tsx`.

## Deployed instance

Secrets (`MONGODB_URI`, `AUTH_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`) are generated by Terraform and mounted from Secrets Manager `refplatform/apps/simple-cms`. `AUTH_URL` comes from SSM. After the first deploy, seed the database through a port-forward: see `terraform/apps/README.md` → "simple-cms admin user".
